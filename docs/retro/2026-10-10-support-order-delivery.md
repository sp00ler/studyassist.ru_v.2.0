## Найдено и исправлено

1. `scripts/support-poll.js` пересылал ответы в защищённый `/api/telegram/webhook` без заголовка авторизации. Получал 403, но сдвигал offset и подтверждал потерянный update. Теперь использует отдельный `/api/telegram/support`, секрет от SUPPORT_BOT_TOKEN и сдвигает offset только после успешного сохранения ответа.
2. Обработчик поддержки работал через основной бот и только в группах. Теперь поддержка отделена от команд заказов, принимает Reply в настроенной группе или личном чате. Записи сохраняются идемпотентно по chat/message ID, удалённая сессия не блокирует очередь.
3. В PM2-конфигурации не было процесса поддержки. В `ecosystem.config.js` добавлен один `studyassist-support-poll`. На сервере требуется проверить существующие poller-процессы, чтобы один токен не обслуживали два экземпляра.
4. Виджет сдвигал курсор при подтверждении собственного сообщения и мог пропустить более ранний ответ оператора. Курсор теперь продвигается только по результатам опроса, сообщения объединяются по ID.
5. Отправки заказов и счетов запускались без ожидания; ошибки внутри allSettled скрывались, интерфейс безусловно сообщал об отправке. Теперь каналы ожидаются независимо; счёт сначала сохраняется, затем отправляется; интерфейс показывает фактический результат каналов. Принятие SMTP/Telegram не равно прочтению или попаданию письма во входящие.
6. Админская заявка сохраняла контакты гостя в заметке, но не в полях клиента. Теперь email обязателен, контакты сохраняются, существующий аккаунт связывается только по явно указанному email. Клиент получает подтверждение; при ошибке каналов админ видит предупреждение и не создаёт дубликат тем же нажатием.
7. Публичная форма теряла выбранные контакты авторизованного клиента. Контакты сохраняются в заявке и имеют приоритет для счёта, чеков и показа в модальном окне.
8. Telegram Markdown мог ломаться на предмете заявки; уведомление переведено на экранированный HTML. Для затронутых отправок согласованы существующие значения по умолчанию адреса сайта и SMTP-пользователя.
